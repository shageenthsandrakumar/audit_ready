AuditReady — The Confidence Model

Hierarchical Bayesian per-part weight model · methodology & open questions
← dashboardconfidence.py

scope This applies only to the decimal_shift_weight class. The five structural classes (duplicates, orphans, impossible values, near-dups, unit drift) use evidence-graded priors in tier1_confidence, not this model.

1. Generative model

Work in $y=\log_{10}(\text{weight})$. Hierarchical, partially pooled across parts $p$:

$$\mu_0,\ \tau,\ \sigma \quad\text{(global mean, between-part SD, within-part SD)}$$ $$\theta_p \sim \mathcal{N}(\mu_0,\ \tau^2)\qquad\text{(per-part true log-weight)}$$ $$y_{pj}\mid\theta_p \sim \mathcal{N}(\theta_p,\ \sigma^2)\qquad(\text{StudentT}_\nu\text{ in the PyMC path})$$

2. Fitting $\theta_p$ — empirical-Bayes default

Conjugate Normal–Normal with robust sufficient statistics so seeded errors don't poison the fit: $\bar y_p=\operatorname{median}_p$, and $\sigma=1.4826\cdot\operatorname{median}(\mathrm{MAD}_p)$.

With $w_{\text{data}}=n_p/\sigma^2$ and $w_{\text{prior}}=1/\tau^2$, the shrinkage posterior (partial pooling):

$$\theta_p=\frac{w_{\text{data}}\,\bar y_p+w_{\text{prior}}\,\mu_0}{w_{\text{data}}+w_{\text{prior}}},\qquad \operatorname{Var}(\theta_p)=\frac{1}{w_{\text{data}}+w_{\text{prior}}}$$ $$\text{pred\_sd}_p=\sqrt{\sigma^2+\operatorname{Var}(\theta_p)}\quad(\text{posterior-predictive SD for a new obs in } p)$$

Rare parts get $\theta_p$ pulled toward $\mu_0$ and a fatter $\text{pred\_sd}_p$ — that's the pooling earning its keep.

3. The error probability

A two-component mixture at the single-observation level — Bayesian $H_0$ vs $H_1$:

$$f_0(y)=\mathcal{N}\!\big(y;\ \theta_p,\ \text{pred\_sd}_p\big)\qquad(\text{genuine})$$ $$f_1(y)=\mathcal{N}\!\big(y;\ \mu_0,\ \sigma_{\text{alt}}{=}2.0\big)\qquad(\text{``error'': broad, } \sim 6 \text{ decades})$$ $$\pi=P(H_1)=0.17\;=\;850/5000$$ $$\boxed{\,P(\text{error}\mid y)=\frac{\pi\,f_1(y)}{\pi\,f_1(y)+(1-\pi)\,f_0(y)}\,}$$

That posterior is the confidence for the weight class. best_decimal_correction is a separate $\arg\max$: it tests $y+k$ for $k\in\{\pm1,\pm2,\pm3\}$ and reports the $k$ whose $f_0(y{+}k)$ beats $f_0(y)$ by $>100\times$.

4. Where it's shaky

Everything hinges on $f_1$, the weakest object in the file:

  1. Location is mis-specified. $H_1$ is centered at $\mu_0$, but a decimal-shift error isn't drawn toward the global mean — it's the part's own truth displaced by an integer, $y\approx\theta_p+k$.
  2. Width is a free Jeffreys–Lindley knob. Near the bulk $f_1\propto 1/\sigma_{\text{alt}}$, so the Bayes factor — and thus $P(\text{error})$ — scales directly with the arbitrary nuisance $\sigma_{\text{alt}}=2.0$. Classic vague-alternative pathology.
  3. Two-step plug-in, not a joint posterior. We fit $\theta$ on (robustly) the inliers, then ask each point $H_0/H_1$ — we never marginalize a latent error-indicator during the fit. The robust median is a band-aid for not modeling the mixture.

5. Proposed fix

Make $H_1$ generative of the actual seeding process instead of a vague Gaussian:

$$f_1(y)=\sum_{k\neq 0} w_k\,\mathcal{N}\!\big(y;\ \theta_p+k,\ \text{pred\_sd}_p\big),\qquad w_k=\text{prior over shift magnitude (e.g. geometric, favoring }\pm1)$$

i.e. “an error looks like the truth shifted by a power of ten.” This (a) removes the location/width arbitrariness — $\sigma$ is shared with $H_0$, no free knob; (b) unifies error_probability and best_decimal_correction — the correction is $\arg\max_k$ of the same components; (c) is honestly the data-generating process.

Calibration without labels

We don't have the answer key, but we know the aggregate: 850 seeded issues. So a label-free, first-moment check:

$$\mathbb{E}[\#\text{errors}]=\sum_i P(\text{error}_i)\ \stackrel{?}{\approx}\ 850.$$

If the posteriors are calibrated in aggregate, that sum lands near the known count — defensible to a judge, no labels required.

6. Open questions (for the modeling lead)

  1. Is the decimal-shift mixture the right $H_1$, or do we add a component for non-shift errors (typos, unit confusion)? What prior $w_k$ over the shift magnitudes?
  2. Is $\sum_i P_i \approx 850$ a legitimate calibration claim, or only a first-moment sanity check we shouldn't oversell? What's the honest framing?
  3. Worth marginalizing the latent error indicator in the fit (a proper mixture / EM) instead of the robust-median plug-in — or is the two-step defensible given the time?
